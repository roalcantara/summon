# Report 1: M3 compliance and Android platform

## Summary
The codebase demonstrates strong Jetpack Compose engineering with high theme fidelity, disciplined dark token usage, robust permission handling, and thorough reduce-motion coverage. All text contrasts comfortably exceed WCAG AAA/AA thresholds (>5.4:1 on obsidian surfaces), touch targets meet or exceed 48 dp, and player text is 100% extracted to string resources across five languages. The most critical release risk is an accessibility blocker where `clearAndSetSemantics` strips `onClick` actions from the Grimoire summon cue, leaving TalkBack and Switch Access users unable to start the ritual; secondary platform risks include missing Android 14+ predictive back declaration in the manifest and several animated values read directly in composition triggering per-frame recompositions.

## Deliberately different, not a gap
- **Dark-fantasy palette only (ADR-0001):** Ships a fixed dark color scheme with obsidian navy surfaces and character accents. No dynamic color (Material You wallpaper theming) and no light theme; the dark tactical RPG atmosphere is the product identity.
- **Orientation locks and letterboxing (ADR-0017 §7):** App declares `android:appCategory="game"` in `AndroidManifest.xml` so Android 17 (API 35+) respects portrait lock for Home/Grimoire and landscape for the Ritual across tablets and foldables without stretching phone layouts.
- **No bottom navigation, navigation drawer, or navigation rail (ADR-0014, ADR-0016):** The application uses a strictly linear game loop (Home → Grimoire → Ritual) managed through `NavHost` without persistent bottom bars or navigation rails.
- **Fixed-size HUD / art slots with capped font scaling (ADR-0033):** Words in fixed art or HUD slots (banner ribbon, seal track numerals, chant feedback line, badges) cap text scaling at 1.3× via `fontScaleCapped()` and shrink to fit, while general body text and rules scroll and scale fully up to 2.0×.
- **Single attention glow (ADR-0033):** Only one breathing cue glows at any time to direct player attention (unbound cue, unread dossier flip button, intro summon button, seeking sigil, or chanting line), avoiding competing visual emphasis.
- **No Floating Action Button (FAB):** Primary actions are integrated into thematic game surfaces (the inlaid grimoire, the stage summoning circle, the tarot card flip button, and the intro parchment button) rather than a stock Material FAB.
- **Rounded 12–24 dp shapes and pills (DESIGN.md / ADR-0001):** Uses friendly rounded corners and pill buttons rather than Stitch's 4px tight chamfered corners, maintaining comedic chibi contrast against dark fantasy lore.

## Needs device check
- **TalkBack traversal on `HorizontalPager` with 10,000 pages:** Confirm on a physical device with TalkBack enabled whether two-finger horizontal page swipes and accessibility focus interact smoothly with the large virtual page count (`initialPage = 5000`).
- **ModalBottomSheet bottom inset on 3-button navigation:** Check whether `SettingsSheet` and `DebugSheet` exhibit extra bottom whitespace when Android 3-button navigation bar is enabled due to `navigationBarsPadding()` inside `ModalBottomSheet`.
- **Landscape display cutout on reverse landscape (270° rotation):** Verify on a device with a physical punch-hole camera that `safeDrawingPadding()` correctly clears the cutout when the phone is held in reverse landscape (cutout on the right edge).
- **Physical hardware keyboard navigation:** Confirm D-pad / arrow key navigation across the Grimoire demon carousel and badges to ensure focus indicators are visible when hardware keys are attached.

## Checked and fine
- **Text contrast:** Every text and icon token against its intended background exceeds WCAG AAA/AA contrast: `onSurface` on background is 14.3:1; `primary` (gold) on background is 11.6:1; `asmodeus` accent is 13.1:1; `astaroth` accent is 5.5:1; `ritualSafe` green is 10.6:1; `outline` on surface is 5.4:1; `parchmentInk` on parchment gradient is 7.5:1 to 10.9:1; dimmed chant text at 55% alpha maintains 5.0:1.
- **Touch target sizing:** Interactive targets across all screens strictly satisfy the 48×48 dp minimum: `IconButton`s (48 dp), `MenuButton` (48 dp), `StageArrow` (56×75 dp), `DemonCutout` (full stage), `QuoteSlot` (72 dp height), `PrimaryActionButton` (52 dp min height), `SummonButton` (56 dp height), `RoundButton` (36 dp visual inside 48 dp `IconButton` touch target), and `CueChip` (`minimumInteractiveComponentSize()`).
- **Reduce motion support:** `LocalReduceMotion` is checked consistently across all animations: idle grimoire bob/hop stops, floor circle pulsing stops, particle fields and heat shimmers cease emission, jitter stops, sunburst rotation stops, tarot card flip falls back to a 150 ms crossfade, and the summon climax bypasses the flash and scale-up for a gentle fade-in.
- **State preservation & process death:** `GameViewModel` backs `selectedId` with `SavedStateHandle`; `GrimoireScreen` preserves `side`, `restless`, `inkedCodex`, `inkedBattle`, and `tadaFor` via `rememberSaveable`; `RitualScreen` preserves permission states, retry counters, and confirmation dialog state via `rememberSaveable`; `AppNavHost` guards destinations against unloaded progress states.
- **Sensor & mic lifecycle management:** `RitualScreen` connects `setActive(true/false)` to `ON_START` / `ON_STOP`, preventing the focus clock and audio processing from draining battery or running in the background.
- **Configuration changes & orientation:** `MainActivity` registers `orientation|screenSize|screenLayout|smallestScreenSize|keyboardHidden|uiMode|density|fontScale` in `AndroidManifest.xml`, ensuring seamless sensor-landscape transitions without activity restart or audio pipeline teardown.
- **Microphone permission UX:** Robust permission handling in `RitualScreen`: checks `checkSelfPermission` on every resume, differentiates first denial from permanent denial (`shouldShowRequestPermissionRationale`), and transitions action from "Retry" to "Open settings".
- **i18n & translation hygiene:** 100% of player-facing text is parameterized in `res/values*/strings.xml` and `demons.xml` across all five supported languages (en, es, pt-BR, it, fr) with no hardcoded strings in Kotlin; string lengths strictly adhere to the English character budget and are validated by automated tests.
- **Heading semantics:** `TitlePlaque` and `ParchmentRibbon` explicitly set `Modifier.semantics { heading() }` for accessibility outline navigation.
