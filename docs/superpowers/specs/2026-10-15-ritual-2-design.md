## Goal

The MVP stays two demons and three screens, but every piece must feel stunning.
Fix what feels weird in today's ritual (any noise completes a phrase; drifting
silently wipes all progress; no live feedback; success hard-cuts to another screen)
and lift Grimoire and Profile from "settings page" to hero presentation.

One spec, one plan, delivered in phases that each build and run (see "Phases").

## 1. Ritual rules

The ritual is a state machine driven by one input per **20 ms tick**:
`RitualInput(azimuth: Float?, voice: VoiceFrame)`. The ViewModel pairs each mic frame
with the latest azimuth; if the mic is unavailable it emits silent ticks at the same
rate. `dt` is always `RitualConfig.TICK_MS = 20`.

Phases (`RitualPhase`):

1. **Seeking** — not within tolerance. Within 60° of the target, a `ProximityTick`
   effect fires each time the distance enters a new, closer 5° bucket.
2. **Locking** — within tolerance (`HEADING_TOLERANCE_DEG = 20`). After
   `LOCK_HOLD_MS = 600` continuous → `Locked` effect, phase **Chanting**. Leaving
   tolerance before that → Seeking, no effect.
3. **Chanting** — the current phrase (`phrase` 0..3) has `syllableCount` syllables
   from `LatinSyllables.count(phrase)`. `lit` (0..syllableCount) advances by one
   (`SyllableLit` effect) when either:
   - the frame is an **onset** (`voice.onset`) and at least `ONSET_REFRACTORY_MS = 120`
     have passed since the last lit syllable; or
   - voicing has been continuous for `SUSTAIN_SYLLABLE_MS = 350` since the last lit
     syllable (held vowels and slurred chanting still progress, slower).

   Unvoiced frames pause; nothing decays. When `lit == syllableCount`:
   `PhraseComplete(phrase)`, `phrase += 1`, `lit = 0`. After the 4th phrase → **Climax**.
4. **Wavering** — leaving tolerance during Chanting. `DriftWarning` on entry. Voice is
   ignored. Returning within `DRIFT_GRACE_MS = 1500` → back to Chanting, unchanged.
   At 1500 ms → `PhraseLost`, `lit = 0`, phase **Seeking** (completed phrases kept).
5. **Climax** — `ClimaxStart` on entry; all input ignored; after `CLIMAX_MS = 2500`
   → `Summoned`, phase **Done**. The UI derives its animation from
   `climaxFraction = elapsed / CLIMAX_MS`, so the sequence is deterministic.
6. **Done** — terminal; `step` returns the state unchanged with no effects.

Derived values on `RitualState`:
- `inkProgress = (phrase + lit / syllableCount) / 4`, in [0, 1] (1 in Climax/Done).
- `aligned`, `azimuth`, `graceFraction` (Wavering), `climaxFraction` (Climax).

**Mic level for visuals:** the ViewModel also exposes `micLevel` in [0, 1], a smoothed
(attack 40 ms / release 250 ms) RMS normalized against `VOICE_RMS_FLOOR` and
`MIC_LEVEL_CEILING`. It drives glow only, never progress.

**Debug:** "Hold to Chant" replaces mic frames with synthetic voiced frames, an onset
every 250 ms. "Simulate heading" still snaps to `demon.ritualHeading`.

## 2. Voice analysis

`VoiceAnalyzer(sampleRate)` is stateful but pure; `analyze(frame: ShortArray, count): VoiceFrame`.
Frames are 20 ms (`sampleRate * 0.02` samples: 320 at 16 kHz, 882 at 44.1 kHz).

`VoiceFrame(rms: Double, voiced: Boolean, onset: Boolean)`:
- **rms** — as today's `rms()`.
- **voiced** — `rms > VOICE_RMS_FLOOR` (1 200) **and** the normalized
  autocorrelation peak over lags for 70–400 Hz is ≥ `VOICING_MIN_CORRELATION` (0.5).
  Rejects claps, taps, wind and breath (aperiodic) while accepting speech and humming.
- **onset** — `voiced` **and** `rms ≥ ONSET_RATIO` (1.8) × the minimum RMS over the
  previous 5 frames (100 ms). Detects each new syllable's energy rise.

All thresholds live in `RitualConfig`; they are global tuning (ADR-0008), not demon data.

## 3. Syllables

`LatinSyllables.count(text)` and `LatinSyllables.spans(text): List<SyllableSpan>`
(character ranges for karaoke). Rules: split on whitespace and punctuation; within a
word, scan vowels left to right: a diphthong (`AE`, `OE`, `AU`, `EI`, `EU`) is one
syllable nucleus, any other vowel is one nucleus on its own. Vowels: A E I O U Y; a `U`
directly after `Q` is a consonant. Consonants attach to the following nucleus (the last
nucleus takes trailing consonants). Exact Latin scansion is a non-goal; counts only
need to feel right.

Expected counts (tests): `DAEMONIUM` 4 (DAE-MO-NI-UM), `GRATIA` 3, `OBEDIENTES` 5,
`POTENTIAM` 4, `TUI` 2, `QUOD` 1.

## 4. Sigils

**Source** (recorded in DESIGN.md):
- Asmodeus: `File:Seal_of_Asmodeus.svg` (Wikimedia Commons, CC0).
- Astaroth: `File:Astaroth_Seal.svg` (Wikimedia Commons, public domain; Mathers & Crowley 1904).

**Authoring.** Each seal's inner glyph is traced by hand into stroke-only paths in a
`0 0 100 100` viewBox and saved as `art/sigils/<id>.svg` (a new tracked folder, not
`reference/`). Paths are grouped as `<g id="ink-1">` … `<g id="ink-4">`; document
order inside a group is draw order. Filled dots become small circles drawn as paths
(`M cx-r,cy a r,r 0 1,0 2r,0 a r,r 0 1,0 -2r,0`). The outer rings and rim lettering
are **not** in the file; `InkedSigil` draws them in code.

**Packaging.** `tools/sigil_to_raw.py` converts `art/sigils/<id>.svg` to
`app/src/main/res/raw/sigil_<id>.txt`: one line per path, `<group> <path-data>`.
`Demon.sigil` becomes `@RawRes Int`.

**Runtime.** `SigilPaths.parse(lines)` → `List<SigilStroke(group, pathData)>` (pure,
tested). `InkedSigil(strokes, inkProgress, accent, micLevel, rimText)`:
- group *g* (1..4) inks over `inkProgress ∈ [(g-1)/4, g/4]`; within a group, strokes
  ink sequentially in proportion to their measured lengths (`PathMeasure.getSegment`).
- outer double ring inks in on `Locked` (ring progress is a separate `ringProgress`
  animated by the UI); rim letters (`demon.name`, Cinzel, spaced around the ring)
  fade in letter by letter with it.
- glow: the inked strokes drawn twice more underneath, wider and translucent, with
  alpha and width scaled by `micLevel`; on API 31+ the glow layer uses
  `Modifier.blur`/`BlurEffect`.
- `inkProgress = 1` renders the complete seal (used by Grimoire and Profile).

### Grimoire — hero pager

`Scaffold` top bar (logo + "My Grimoire"), body `HorizontalPager` over the catalog.
Each page, back to front:
1. `sceneArt`, `ContentScale.Crop`, darkened (scrim from `surfaceContainerLowest`);
   blurred on API 31+.
2. `InkedSigil` at `inkProgress = 1`, slowly rotating, alpha 0.15 (locked) / 0.3 (unlocked).
3. `EmberField` particles + `HeatShimmer` (accent-tinted).
4. Cut-out with `GyroParallax` and a gentle float. Locked: near-black silhouette tint,
   accent rim light, drifting `SmokeField`. Unlocked: full colour.
5. Name (display), then title (unlocked) or "Sealed · Face {direction} to summon"
   (locked), then `PrimaryActionButton` **Summon** / **View**.

Page indicator: a row of avatars (circle-clipped; greyscale while locked; selected one
enlarged with accent ring). Tapping an avatar scrolls to its page.

### Ritual — full-bleed altar

Background `background` + faint `EmberField`. Top row: demon name (label) and an ✕
icon button (abort). Centre: `InkedSigil` (~80% width) wrapped by `CompassArc`
(current heading marker, target notch; `outline` while Seeking, `ritual-safe` on
lock, `error` pulsing while Wavering with a draining arc = `graceFraction`).
Phase hint below (Cinzel title):

| Phase | Hint |
|---|---|
| Seeking | "Turn left" / "Turn right" toward {direction} |
| Locking | "Hold steady…" |
| Chanting | "Chant!" |
| Wavering | "Return {direction}!" |
| Mic denied / unavailable | existing rationale / banner copy |

Chant stack: completed phrases small and accent-coloured; the current phrase large
with **karaoke** fill (lit syllables in accent, a soft glow on the newest);
upcoming phrases dim (`outline`). Debug controls below in debug builds.

**Climax** (`climaxFraction` 0→1): 0–0.3 scrim dims to 85% and UI chrome fades;
0–0.6 particles converge on the sigil; 0.6–0.7 flash (accent → white radial);
0.7–1.0 the cut-out rises from the sigil centre (scale 0.4→1, translate up,
silhouette→colour). On `Summoned`: unlock + navigate to Profile; the cut-out is a
shared element (`demon-art-{id}`) so it glides into place.

### Profile

Backdrop `sceneArt` dimmed + `RotatingSunburstBackground` + `HeatShimmer`. Hero
cut-out (shared element) floating with parallax. New summon: `RibbonBanner`, tada
(once, as today). Bottom panel (`surfaceContainer`, top-rounded `large`, scrollable):
name, title, description, quote. CTA pinned below: **Awesome!** / **Back**. Debug
builds in view mode add an outlined **Unsummon** button (calls
`DemonViewModel.lock(id)`, pops to Grimoire).

Grimoire **View** also uses the shared element, Grimoire cut-out → Profile cut-out.

### Motion safety

`LocalReduceMotion` = `Settings.Global.ANIMATOR_DURATION_SCALE == 0`. When true:
no particles, parallax, float, shimmer, sunburst rotation or climax particles; the
climax collapses to a 500 ms fade; ink and karaoke still update.

## 6. Audio

`tools/gen_audio.py` (stdlib only; replaces `gen_tada.py`) writes CC0 mono
22.05 kHz WAVs to `res/raw/`:

| File | Sound |
|---|---|
| `bed_asmodeus` | ~8 s seamless loop: warm low drone (root + fifth), slow tremolo, faint crackle noise |
| `bed_astaroth` | ~8 s seamless loop: detuned minor-third pad, slow chorus, high shimmer |
| `chime_1`…`chime_4` | bell tone, one pentatonic step higher per phrase |
| `lock` | low thud + short shimmer |
| `riser` | ~2 s noise + pitch sweep |
| `boom` | sub hit with tail |
| `tada` | improved fanfare (≤ 2 s) |

`platform/RitualSounds`: `SoundPool` for one-shots; looping `MediaPlayer` for the bed.
Bed fades in on `Locked`, ducks to 30% while Wavering, swells in Climax, fades out on
`Summoned` or leaving the screen. Released on `ON_STOP`. Requests transient audio focus;
pauses the bed when focus is lost.

## 7. Haptics

`platform/Haptics` gains: `tick` (`EFFECT_TICK` 29+), `clunk` (`EFFECT_HEAVY_CLICK` 29+),
`warn` (two 40 ms pulses), `syllable` (very light, ≥ 120 ms apart), `chime` (medium
click), `crescendo` (2 s waveform, amplitude 40→255, final 140 ms burst) and the existing
`success`. Older APIs/no amplitude control → timing-only fallbacks; no vibrator → no-op.

Effect → feedback (`platform/RitualFeedback`, collects `RitualViewModel.effects`):

| Effect | Haptic | Sound |
|---|---|---|
| `ProximityTick` | tick | — |
| `Locked` | clunk | lock; bed fades in |
| `SyllableLit` | syllable | — |
| `PhraseComplete(n)` | chime | `chime_{n+1}` |
| `DriftWarning` | warn | bed ducks |
| `PhraseLost` | warn | — |
| `ClimaxStart` | crescendo | riser |
| `Summoned` | success | boom |

## 8. FX

- `ui/fx/HeatShimmer`: AGSL `RuntimeShader` (API 33+) applied via
  `RenderEffect.createRuntimeShaderEffect` as a `graphicsLayer` render effect —
  a vertical sine displacement + accent bloom driven by time. Below 33: a slow
  vertical accent gradient breathing in alpha.
- `ui/fx/EmberField`, `SmokeField`, converging climax particles: one Canvas particle
  system (`ParticleField`) with deterministic seeds, frame-clock driven.
- `ui/fx/GyroParallax`: `rememberParallax()` reads `TYPE_GAME_ROTATION_VECTOR`
  (fallback gyroscope-less: none) and returns a small `Offset` (max 12 dp), low-passed;
  sensor unregistered when not composed.

All FX composables read colors from the theme/accent only (DESIGN.md rules).

## 10. Error handling

| Case | Behaviour |
|---|---|
| Mic denied | Existing rationale + retry / Settings; hint shows why; chanting cannot progress. |
| Mic stops mid-ritual | Banner; silent ticks continue, so the ritual just can't progress (no penalty beyond normal drift rules). |
| No heading sensor | Banner "This device can't sense direction"; debug builds can still Simulate heading. |
| No vibrator / no amplitude control | Silent or timing-only fallback. |
| API < 33 / < 31 | Gradient instead of AGSL shimmer; dim instead of blur. |
| No game-rotation sensor | Parallax disabled. |
| Audio focus lost | Bed pauses; one-shots still play. |

## 11. Testing

JVM unit tests (existing pattern; no instrumented tests):
- `VoiceAnalyzerTest`: 150 Hz sine above floor → voiced; white noise and a 20 ms
  click → not voiced; silence → nothing; on/off 150 Hz bursts (200 ms on, 100 ms off)
  → one onset per burst; 44.1 kHz frames work too.
- `LatinSyllablesTest`: counts listed in §3; spans cover all letters of each word.
- `RitualEngineTest`: seek → lock at exactly 600 ms; lock aborted by leaving; proximity
  ticks only on closer buckets; onset lights a syllable; refractory blocks a second
  onset within 120 ms; 350 ms sustained voicing lights one; unvoiced frames pause;
  phrase completion and effect; return within 1 499 ms keeps `lit`; 1 500 ms →
  `PhraseLost`, `lit = 0`, Seeking, completed phrases kept; climax ignores input;
  `Summoned` exactly once at 2 500 ms; Done is terminal; `inkProgress` values.
- `SigilPathsTest`: parsing, group ordering, ink fraction math at group boundaries.
- `RitualViewModelTest` (rewritten): fake heading + PCM sources; simulate/hold-to-chant;
  mic failure → `micUnavailable`; effects emitted in order.
- `DemonViewModelTest`: `lock(id)`.
- `DemonCatalogTest`: every demon has a sigil, cut-out, scene, avatar, bed.

Manual device checklist (in the plan): both summons end to end; drift with return and
without; humming vs chanting vs clapping; mic denial; reduced motion; API 24 emulator
(fallbacks); API 33+ device (shader).
