# Internationalization (i18n): design

- **Date:** 2026-10-20
- **Status:** Approved in conversation; pending implementation plan
- **Languages:** English (source), Spanish (`es`), Brazilian Portuguese (`pt-BR`), Italian (`it`), French (`fr`)
- **Decision record:** ADR-0031 (written with the implementation)

## 1. Goal

Ship the game in five languages at once. Everything a player reads is translated: screen text,
demon lore, House and Calling badges, the Play Store listing and the privacy policy. No
translation is longer than its English source, so the layout stays as it is.

## 2. Decisions

| Topic | Decision |
|---|---|
| Languages | en, es, pt-BR, it, fr, all in one release |
| Translator | Claude drafts all four. The owner reviews pt-BR on device; es, it and fr ship as reviewed drafts |
| Scope | Everything players read: UI, demon lore, badges, store listing, privacy policy |
| Chant | Latin in every language; chant check and its calibration unchanged |
| Language choice | Device language; Android 13+ per-app language in system Settings; English fallback; no in-game picker |
| Length | Each translation has at most the English character count. A unit test enforces it; reviewed exceptions sit in a list |
| Storage | Android string resources for all text (approach A) |
| App name | "Summon Demons Safely" stays English (the logo art has it drawn in) |

## 3. Where the text lives

### 3.1 Resources

Each language has two files, plus English debug text that is never translated:

| File | Content |
|---|---|
| `res/values*/strings.xml` | Screen text (today's file, minus the debug strings) |
| `res/values*/demons.xml` | Demon lore, House tooltips, Calling labels and tooltips |
| `res/values/strings_debug.xml` | Debug panel and debug controls; `translatable="false"`, English only |

English is in `values/`; translations are in `values-es/`, `values-pt-rBR/`, `values-it/`,
`values-fr/`. `app_name` is `translatable="false"`.

Demon keys: `demon_<id>_<field>`, for example `demon_asmodeus_title`, `demon_asmodeus_offices`
(a `<string-array>`), `demon_asmodeus_ability_1_name`, `demon_asmodeus_ability_1_line`,
`demon_asmodeus_weakness_name`. Houses: `house_<id>_tooltip`. Callings: `calling_<id>_label`,
`calling_<id>_tooltip`.

### 3.2 Data model

- `Demon`: `title`, `description`, `quote`, `restlessQuote`, `appearance`, `warning`, `secret`,
  `rank` and `liege` change from `String` to `@StringRes Int` (`liege` stays nullable).
  `offices` becomes `@ArrayRes Int`. `Ability` holds `@StringRes name` and `@StringRes line`.
- Plain strings in every language: `name` (Asmodeus, Astaroth), `chantPhrases` (Latin), and
  `House.planet` (Sol, Venus).
- `House.tooltip`, `Calling.label` and `Calling.tooltip` become `@StringRes Int`.
- Composables resolve text with `stringResource(...)` / `stringArrayResource(...)`. Only the UI
  reads demon text today (`GrimoireScreen`, `Badges`, `DossierCarousel`).

### 3.3 PRODUCT.md stays the source

PRODUCT.md remains the source of truth for the English demon text. `DemonCatalogTest` checks
that `values/demons.xml` matches it, through a small XML reader that runs in plain JVM unit
tests (no Robolectric, no emulator).

## 4. Language selection and grammar

- `androidResources { generateLocaleConfig = true }` and `res/resources.properties` with
  `unqualifiedResLocale=en`. The build writes the locale config and adds it to the manifest.
- Android 13+: device language plus the per-app choice in Settings › Apps › Summon Demons Safely
  › Language. Android 7–12: device language. Any other language: English. No AppCompat and no
  in-game picker.
- Plurals: these strings become `<plurals>`, with the quantity named per string:

  | Key | Quantity |
  |---|---|
  | `home_bound` | total spirits (`%2$d`) |
  | `cd_cooling` | hours |
  | `badge_legions_label`, `badge_legions_text` | legions |
  | `chant_a11y_seals` | lines sealed |

  `quote_next_summon` ("h") and `dossier_page` ("1 / 6") stay plain strings.
- Gender: demons are male in the lore, so translations agree with him. Translations never give
  the player a gender; they use imperatives and neutral phrasing.
- Numbers are formatted by `stringResource` in the current language. Uppercasing keeps
  `Locale.ROOT`, which is correct for all five languages.
- Fixed symbols stay in code: "·", "✓", "↺", "✕", "←". The chant score becomes a string,
  `chant_score`: "%1$d%%" in English (today it renders "85 %"; it becomes "85%"), "%1$d %%" in French.

## 5. Checks

### 5.1 `TranslationResourcesTest` (JVM unit test)

Uses the XML reader from 3.3 on `values/` and each `values-*/` folder.

1. **Completeness:** every translatable English key exists in each language, and no extra keys
   exist. String arrays have the same item count. Each plural has the quantity forms its language
   needs (`one`/`other` for all five; `many` where CLDR requires it, e.g. fr, es, it, pt).
2. **Placeholders:** each translation has the same set of format specifiers as English
   (`%1$s`, `%2$d`, `%%`).
3. **Length:** each translation's length is at most the English one, counted after unescaping
   (`\'` is one character, `&amp;` is one). Placeholders count as written. Plural forms are
   compared with English's longest form; string arrays item by item.
4. **Exceptions:** `app/src/test/resources/i18n/length-exceptions.txt` holds one per line:
   `<locale> <key> <reason>`. The test fails if a listed exception no longer exceeds the English
   length, so the list cannot go stale.
5. **Glyphs:** every character in every translation exists in both bundled font families (Cinzel
   and Inter, `res/font/*.ttf`), checked with `java.awt.Font.canDisplay`.

### 5.2 Build

- Lint `MissingTranslation` is an error.
- Debug builds enable pseudo-locales (`isPseudoLocalesEnabled = true`). English (XA) shows
  padded, accented text, which shows clipping and any text still hard-coded in Kotlin.

### 5.3 Existing tests

`DemonCatalogTest` reads English text from `values/demons.xml` and checks that every resource id
in `DemonCatalog` exists. Ritual, chant check and session replay tests are unchanged: they read
no player text.

## 6. Translation workflow

1. `docs/i18n/glossary.md`: each game term fixed once per language before translating:
   summon, seal, sealed, bound, restless, escaped, Grimoire, court, House, Calling, legions,
   liege, ranks (Great King, Duke, …), Callings (Warlord, Tutor, Oracle, Treasurer, Menace).
2. `docs/i18n/style.md`: no longer than English; keep the joke rather than the words; never give
   the player a gender; leave names, planets and the Latin chant alone; local punctuation
   (French « » and a space before ! ? : ; Spanish ¡ ¿).
3. Claude drafts es, pt-BR, it and fr from the English resources, with PRODUCT.md for context,
   then re-reads each against the glossary and the length test.
4. The owner reviews pt-BR on device.

## 7. Store and policy

- `docs/store/STORE_LISTING.<lang>.md` for es, pt-BR, it, fr: short description (≤ 80) and full
  description (≤ 4000), with character counts noted as in `docs/STORE_LISTING.md`. The app name
  stays English.
- `docs/PRIVACY_POLICY.<lang>.md` for the same four languages. The English policy is
  authoritative; each translation says so in its first line.
- Screenshots stay English for this release.

## 8. Docs

- PRODUCT.md: supported languages, Latin chant in every language, the English-length rule.
- DESIGN.md: layout must fit the English text length; check with English (XA).
- AGENTS.md conventions: all player text lives in resources; a new string needs all five
  languages and must pass `TranslationResourcesTest`.
- ADR-0031: the decisions in section 2.

## 9. Manual verification

On the phone and the emulator, once per language (switched in system Settings): Home; Grimoire
with a sealed, a bound and a restless demon; the demon card with every dossier page; badges and
their tooltips; the chant intro; Ritual and Chant screens (locked, chanting, sealed, failed); the
escape banner. Then one pass in English (XA), and one check that a German device falls back to
English. Each screen gets a pass/fail note in the plan's checklist; the owner reviews pt-BR
wording on this pass.

## 10. Done when

1. All five languages are complete and pass `TranslationResourcesTest` and lint.
2. The manual pass is clean in all five languages and English (XA).
3. The owner has approved pt-BR.
4. Store listings and privacy policies exist in all four languages within Play's limits.
5. ADR-0031 and the PRODUCT, DESIGN and AGENTS updates are committed.

## 11. Risks

- **Length vs. jokes:** some punchlines may not fit. The exception list is the escape valve;
  tooltips and lore wrap freely.
- **Cinzel coverage:** if Cinzel lacks a character, the fix is a fallback font for it, not
  changing the text. The glyph test finds this early.
- **es, it, fr without native review:** awkward humour is an accepted risk; tester feedback can
  improve them later.

## 12. Non-goals

Translated app name or logo; in-game language picker; a localized chant; localized
screenshots; right-to-left languages; translating debug text.
